# test10 EA

MT5用のマルチタイムフレームEAです。戦略の確定仕様は本書を基準とします。

## 1. フレームの役割

- H1: ADX、DI+、DI-、EMA20、EMA50を用いて相場環境とTrendStateを判定する。
- M15: RSIとMACDを計算し、MACD CrossとDivergenceを判定する。実際の追撃抑制判定ではRSIのみを用いる。
- M1: SuperTrend、BB、ATR、M1 Stochasticを使って実際の取引タイミングを判定する。
- OnTimerは足更新時の計算と事前判定を行い、OnTickは監視・発注・決済・SL更新を行う。

## 2. CopyBufferと足番号

CopyBufferの配列は、EA内部で次の意味を統一する。

- [0] = 現在形成中の未確定足
- [1] = 直近の確定足
- [2] = 2本前の確定足
- [3] = 3本前の確定足
- 以下同様

Arrayをシフトして [0] = 直近確定足 とする実装は行わない。

確定済み14本を使用する場合は、対象を必ず [1] ～ [14] とする。未確定足 [0] を含めた [0] ～ [13] を「確定済み14本」として扱わない。

この規約は価格データ、各種インジケータデータに共通して適用する。

## 3. TrendState

TrendStateの詳細分類は維持する。判定自体を簡略化しない。

H1のTrendStateは直近3本の確定ADXを時系列順の [3]、[2]、[1] で比較して判定する。

- TREND_ACCELERATE: 25 <= [3] < [2] < [1]
- TREND_DECELERATE: [3] > [2] > [1] >= 25
- TREND_REACCELERATE, TREND_RECOVERY_MAINTAIN, TREND_STALL_MAINTAIN, TREND_MAINTAIN, RANGE_MAINTAIN, RANGE_TO_TREND, TREND_TO_RANGE, STATE_UNKNOWN も同様に分類する。

ただし、取引ロジックでは維持系の状態を必要に応じて同一処理にまとめる。

## 4. SuperTrendとATR

- 既存EAでM1に使っているATR期間を変更しない。
- ATR期間は input に追加しない。
- SuperTrendラインは既存のSuperTrend方式を基本にし、ATRを使う動的なラインとする。
- SuperTrend ATR倍率は内部変数とする。
- 初期値: SuperTrend ATR倍率 = 3.0
- この3.0はライン計算用であり、Pullback/Reacceleration判定幅にはそのまま使わない。

Pullback/Reaccelerationは、SuperTrendラインに対する価格の位置・距離をATR基準で判定する。

- Pullback判定倍率 = 0.3 ATR
- Reacceleration判定倍率 = 0.2 ATR
- これらは input ではなく内部変数とする。
- 固定point値や固定pips値による判定は行わない。

## 5. M15 MACD

M15 MACDは計算・Cross判定・Divergence判定のために使うが、追撃フィルタとしては使わない。

- MAINとSIGNALは iMACD から取得する。
- HISTOGRAMは MAIN - SIGNAL をEA内部で計算する。
- Crossは確定足のみで判定する。
- 判定対象は [1] と [2] を比較する。
- 未確定足 [0] は Cross 判定に使わない。

## 6. Divergence

Divergence対象は価格、M15 RSI、M15 MACD Histogram とする。

- 対象範囲: 直近14本の確定足
- 使用範囲: [1] ～ [14]
- 未確定足 [0] を含めない
- 可能な限り14本分を配列として一括取得する
- 取得した配列の元位置を保持し、値だけを並べ替えて位置を失う実装はしない

ピーク候補は、

- 高値側のピーク候補
- 安値側のピーク候補

を抽出する。各候補は値と元の配列位置をセットで管理する。

- 同値ピークを排除しない
- 隣接ピークは直近側を採用し、古い側を破棄する
- 必要なら次の候補を採用する
- 時系列順に並べたピークの推移から、上昇・下降・横ばい・その他・コンフリクトを判定する

価格側のピーク推移と指標側のピーク推移を比較し、方向が逆転している場合をDivergenceとする。

価格と指標のピーク足位置は同一である必要はない。時間的な推移で比較する。

CONFLICT は判定するが、取引ロジックでは DIVERGENCE_NONE と同じ扱いとする。

## 7. M15 RSI追撃フィルタ

M15の実際の追撃抑制判定に使うのはRSIのみとする。

BUY:

- RSI < 70 => 追撃禁止
- RSI >= 70 => 追撃可能

SELL:

- RSI > 30 => 追撃禁止
- RSI <= 30 => 追撃可能

RSIが30～70の範囲にある場合は、BUY/SELLとも追撃禁止である。

M15フィルタの有効期間は、M15確定後の直後のM1足のみとする。

- M15確定
- 次のM1足でフィルタON
- そのM1足が終了して次のM1足へ移行した時点でOFF

M15側で複数の抑制条件を実装する場合、どれか1つでも抑制条件を満たした場合は追撃禁止とする。実質的には、すべてのフィルタが追撃を許可した場合のみ追撃可能とする。

## 8. M15 StochasticとM1 Stochastic

- M15 Stochasticは使用しない
- M1 Stochasticは既存仕様を維持する
- M1 Stochastic設定: %K = 5, %D = 3, slowing = 3

## 9. SL更新

SLは同一方向のポジションで統一する仕様を維持する。

- BUY用newSL、SELL用newSLを毎Tick計算する
- ポジション数確認の前後にかかわらずnewSL計算自体は行う
- その後、各ポジションについて以下を確認する
  - ポジションが存在しない場合: 比較・更新しない
  - ポジションが存在する場合: currentSLとnewSLを比較する

更新禁止条件:

- 現在SLとnewSLが同一
- 現在SLより不利になる
- 最低更新幅未満

最低更新幅は point 単位の内部設定とする。

SL更新のリクエストは、現時点では送信回数制限を行わない。

## 10. リクエスト数管理

直近60秒間のリクエスト数を管理する。

- リクエスト発生時に履歴を追加する
- 古い履歴を除外したうえで、現在時刻から60秒以内の件数を算出する
- 履歴は時間順に保持する
- 処理方式の基本: 古い履歴から順に確認し、60秒内の最初の履歴を探し、それより古い履歴を削除して残りを数える
- datetimeの秒単位で管理する
- 厳密なミリ秒管理はしない

ログ表示基準:

- 直近60秒のリクエスト数が20件を超えた場合にログを表示する
- 20件という値は input ではなく内部変数とする

## 11. リクエスト結果の評価

リクエスト結果は以下を区別して管理する。

1. 送信失敗
2. 実行失敗
3. 実行成功
4. リクエスト数

ログ表示もこの順番とする。

送信自体が失敗した場合と、サーバーへ送信された後の実行失敗を、EA側で判別可能な範囲で区別する。完全判定不能な場合は推測で判定しない。

## 12. OnTrade / OnTradeTransaction

- 1回の取引に対してOnTradeが複数回呼ばれる可能性があるため、OnTradeを1回だけ実行される前提で設計しない
- OnTradeTransactionでは transaction type と request/result の内容を確認し、必要に応じて注文送信・注文変更・注文削除・約定・履歴追加・ポジション変更・リクエスト結果を分類する
- 「必ず1取引につき1ログ」にするような複雑な監視機構は追加しない
- 同一内容のログが複数回出力されても許容する

## 13. 修正対象外

今回明示的に変更していない既存仕様は変更しない。

- H1による環境判断
- M1による実際の取引判断
- M15による追撃抑制
- 既存の各指標期間
- 既存の取引条件
- SL/TP関連仕様
- ポジション管理

上記以外の部分のみ、既存コードとの整合性を考慮して実装する。
