# test10 EA v3.10

MT5用のマルチタイムフレームEAです。判定は確定足の指標値を中心に行い、発注・決済はOnTickの現在価格で実行します。

## 時間足の役割

- H1はADX、DI+、DI-、短期EMA、長期EMAで相場環境、方向、トレンド状態を判定します。
- M15はRSI、MACD Main、MACD Signal、MACD Histogram、MACDクロスを計算します。追撃許可に使う指標はRSIです。
- M1はATR、Bollinger Bands、Stochastic %K/%D、SuperTrendでエントリー・決済タイミングを判定します。
- OnTimerは新しい確定足を検出し、M1、M15、H1の順に各時間足を更新します。

内部の配列は、`[0]`が形成中の未確定足、`[1]`が直近確定足、`[2]`以降が過去の確定足です。確定足の判定では`[1]`以降を使用します。

## H1判定

ADXの強弱、DI差、DI方向、EMAの位置関係から、レンジ、弱いトレンド、強いトレンド、不明を分類します。ADXの確定足3本の推移から、加速、減速、再加速、レンジとの移行などの状態も判定します。

## M15判定と追撃抑制

RSI 70以上を買われすぎ、30以下を売られすぎとして保持します。MACDのMain、Signal、Histogramとクロスは計算・ログ出力しますが、MACDは追撃の許可・禁止には使用しません。

強トレンドの追撃は次の条件で許可します。

- BUY: RSIが70以上
- SELL: RSIが30以下

M15確定直後のM1足では、RSI条件により追撃を抑制します。そのM1足が終わって次のM1足へ移ると抑制は解除されます。

## M1とSuperTrend

M1ではBB期間20、偏差2、Stochastic K=5/D=3、ATR期間14を使用します。SuperTrendのATR倍率は3.0です。

SuperTrendは起動時に過去50本のM1価格とATRを取得して、古い足から直近確定足まで初期計算します。初期化に失敗してもEAは停止せず、次のM1確定足更新で再試行します。初期化後は保存した直近状態と新しい確定足だけで更新し、毎回履歴全体を再計算しません。

トレンド相場ではSuperTrendの方向・反転・再加速をエントリー判定に使用します。Pullback幅は0.3 ATR、Reacceleration幅は0.2 ATRです。閾値はM1更新時に計算し、PullbackとReaccelerationは同一M1足内の現在Ask/Bidで判定します。Pullback状態はM1更新時にリセットします。

## エントリー

レンジでは、価格がBB下側または上側を一度抜けた後、BB側へ戻ったときにエントリーします。BUYはRSIが30以下、SELLはRSIが70以上である必要があります。また、BB幅が最低SL幅の1.5倍以上である必要があります。

最大許容スプレッド以下であることも必要です。スプレッド条件とBB幅条件は別々に判定し、両方を満たした場合だけレンジエントリーを許可します。

トレンドではH1のDI方向と一致する方向だけを許可し、通常は同一方向1ポジションまで、強トレンドの条件を満たす追撃を含めて最大3ポジションまでとします。

## 決済

レンジの通常決済は、BUYがBB上側、SELLがBB下側へ接触した場合です。Stochasticのクロスまたは過熱圏からの反転でも決済します。

トレンドの通常決済はSuperTrendです。緊急決済として、Stochasticクロス、過熱圏からの反転、BB中帯の突破をOR条件で使用します。既存のSuperTrend決済は維持しています。

SLは現在価格から固定ポイント幅で設定し、トレンドではSuperTrendを候補にトレーリングします。候補SLが現在SLより有利で、最低更新幅以上離れている場合は、毎Tick更新を試行します。不利な方向への更新は行いません。

## リクエストと取引ログ

発注、決済、SL/TP変更のリクエストは、送信試行ごとに時刻を記録し、直近60秒だけ保持します。送信失敗、実行失敗、実行成功、直近60秒のリクエスト数を管理し、リクエスト数が20件を超えた状態でリクエストが発生した場合にログを出力します。

OnTradeは空のイベントとして残し、実取引の内容とその時点の買い・売り・合計ポジション数はOnTradeTransactionでログ表示します。MT5のイベント仕様により同じ取引について複数回ログが出る場合があります。

## ロット

基本ロットを基準に、レンジ、トレンド初撃、強トレンド追撃で倍率を変えます。最大ロット制限と資金連動ロットは現時点では使用していません。将来的に固定方式と変動方式を選択できるようにする予定です。

## Divergence

Divergenceは将来実装予定です。判定方法は現在検討中で、現時点では売買判定に使用していません。計算用の関数と構造は将来接続できるよう保持しています。
