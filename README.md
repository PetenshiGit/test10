# test10 EA

MT5用のマルチタイムフレームEAです。戦略の確定仕様は本書を基準とします。

## 時間足の役割

- **H1**: ADX、DI+、DI-、EMA20、EMA50で市場環境、方向、強弱、TrendStateを判定する。
- **M15**: RSI、MACD、確定足クロス、ダイバージェンスを計算し、主に追撃抑制用の補助情報を作る。
- **M1**: SuperTrend、Bollinger Bands、Stochastic、ATRで発注・決済のタイミングと価格を計算する。
- `OnTimer`は確定足の更新と事前計算、`OnTick`は価格監視、発注、決済、SL更新を担当する。

## H1判定

ADXの閾値はトレンド`25`、レンジ`18`、強トレンド`40`。`18以上25未満`は判定不能または遷移状態とする。DI差が`12`未満なら方向不能、`12以上`ならDI+優位を上昇、DI-優位を下降とする。通常の方向はDIを優先し、EMA20とEMA50は補助情報として使う。強トレンドの追撃ではDI方向とEMA方向の一致を必須とする。

TrendStateは直近3本の確定ADX、つまり時系列の`[3]`、`[2]`、`[1]`で毎回判定する。`TREND_ACCELERATE`は`25 <= [3] < [2] < [1]`、`TREND_DECELERATE`は`[3] > [2] > [1] >= 25`とする。再加速、回復維持、失速維持、維持、レンジ維持、`RANGE_TO_TREND`、`TREND_TO_RANGE`、`STATE_UNKNOWN`も分類し、レンジまたは判定不能時はTrendStateを売買判断に採用しない。維持は横ばいだけを意味しない。

## M15フィルタ

初撃はH1とM1を主軸とし、M15逆行シグナルを恒常的な停止条件にしない。追撃だけ、RSI、ダイバージェンス、MACDクロスをAND条件で判定する。BUYはRSI`>= 70`、SELLはRSI`<= 30`。BUYに対する弱気、SELLに対する強気のダイバージェンス、追撃方向と逆向きのMACDクロスがあれば追撃しない。

M15シグナルは15分間保持しない。1個でも複数でも寿命は同じで、M15確定後の最初のM1足だけ有効とする。MACDクロスは確定足`[2]`から`[1]`へのMAIN/SIGNALの入れ替わりで判定し、未確定足`[0]`は使わない。RSIは決済の必須条件ではない。

ダイバージェンスは直近14本の確定足を対象とし、価格と指標を独立に処理する。隣接候補は直近側を残し、値の大小から3点を選んで時間順に並べる。3点が全上昇または全下降の場合だけ分類し、それ以外はその他とする。価格上昇・指標下降は弱気、価格下降・指標上昇は強気。強気と弱気の競合は`DIVERGENCE_CONFLICT`として記録するが、取引上は`DIVERGENCE_NONE`相当とする。

## M1エントリーと決済

トレンド初撃はSuperTrendの方向転換、クロス、またはレンジからトレンドへの移行後を対象とする。強トレンド追撃は、価格がSuperTrendへ近づいた後に再び離れる状態遷移を必須とする。`PullbackBuffer=0.03`、`EntryBuffer=0.02`で、単なる現在価格の位置だけでは追撃しない。

レンジはBB接触後の戻りを発注起点とし、RSIとStochasticをタイミング補助に使う。トレンド保有中にSuperTrendを逆方向へ明確に割った場合は同方向ポジションを全決済する。StochasticはM1決済およびレンジのタイミング用途として残す。

## ポジションと発注制御

- 両建てを許可し、BUYとSELLの制御を独立させる。
- 通常は同方向1ポジション、強トレンド時だけ追撃を許可する。
- 基準ロットは`BaseLot`固定。トレンド初撃`1.0`、レンジ`0.7`、強トレンド追撃`0.5`倍とする。
- ブローカーの最小ロットとステップで正規化し、資金連動ロットは使わない。
- 決済した同一M1足では同方向へ再発注しない。発注した足での決済は許可する。
- 同方向の最終発注バー時刻と最終決済バー時刻を独立管理する。

## SLとリクエスト管理

発注時にサーバー側SLを設定する。BUY用・SELL用の`newSL`はポジション数にかかわらず毎ティック計算し、各ポジションの現在SLと比較する。更新は有利な方向、同一値でないこと、`MinSLUpdatePoints`以上の差（単位はpoint）をすべて満たす場合だけ行う。同一Tickで再送せず、失敗時は内部SLを成功扱いにしない。

取引リクエストは時刻と結果を対応づけた履歴で管理し、現在時刻から過去60秒より古い記録を削除する。固定1分区間の集計や、件数上限到達による一律停止は行わない。20件を超えた場合だけ、次の日本語ログを表示する。

`送信失敗：○件 / 実行失敗：○件 / 実行成功：○件 / リクエスト数：○件`

`OrderSend`等の関数戻り値による送信成否と、`ResultRetcode`等によるサーバー実行結果を別々に記録する。

## 時系列データと未確定事項

CopyBufferおよびOHLCの番号は`[0]`が未確定足、`[1]`が直近確定足、`[2]`が1本前、`[3]`が2本前。今回の戦略では過去の任意Tick価格は使用しない。

Stochasticの詳細な決済条件、週末・休日の運用設定、急変時の追加抑制条件は確定仕様が不足しているため、新規条件を追加しない。
